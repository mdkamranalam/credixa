# 📖 Credixa User Manual

Welcome to the comprehensive User Manual for **Credixa: Next-Gen Education BNPL & Autonomous Underwriting**. This guide will walk you through setting up the platform, navigating as different user personas, and understanding the core AI-driven features.

---

## 1. Introduction
Credixa is a state-of-the-art Buy Now Pay Later (BNPL) financial ecosystem designed specifically for the education sector. It digitizes the entire loan lifecycle, removing the need for legacy credit scores. Instead, Credixa uses an AI Risk Engine to evaluate creditworthiness based on banking behavior, academic performance, and savings habits, generating a proprietary **Omniscore**.

## 2. Getting Started & System Access

Credixa operates on a 5-pillar cloud microservice architecture. You can interact with the live deployed URLs or run the system locally.

### 2.1 Live Cloud Portals
- **Student & Admin Frontend:** [credixa-8wlw.onrender.com](https://credixa-8wlw.onrender.com/)
- **API Gateway Health:** [credixa-backend-7r4k.onrender.com](https://credixa-backend-7r4k.onrender.com/)
- **AI Risk Engine Swagger UI:** [credixa-risk-engine.onrender.com/docs](https://credixa-risk-engine.onrender.com/docs)

### 2.2 Local Development Setup
To run Credixa on your local machine, ensure you have **Docker Desktop** installed.
1. Clone the repository: `git clone https://github.com/mdkamranalam/credixa.git`
2. Navigate to the project directory and configure your environment variables (copy `.env.example` to `.env` inside the `backend-gateway` folder).
3. Run the complete ecosystem with a single command:
   ```bash
   docker-compose up --build
   ```
4. Access the Local Frontend at `http://localhost:5173`.

## 3. User Roles and Workflows

Credixa is designed for multiple personas. Below is the workflow for each type of user.

### 3.1 The Student (Applicant)
The student is the primary borrower seeking educational financing.
* **Registration & Login:** Create a secure account using your email.
* **5-Step Onboarding Workflow:**
  1. **Personal Information:** Enter basic demographic details.
  2. **Educational Details:** Select your institution, program, and current academic score.
  3. **Co-Applicant Details:** Link a parent or guardian as a co-borrower.
  4. **Document Vault:** Upload required KYC (Identity) documents, the academic fee structure, and recent bank statements.
  5. **Review & Submit:** Submit the application for autonomous processing.
* **Student Dashboard:** Once submitted, the AI engine processes the application in under 60 seconds. The dashboard displays the final loan status, the generated Omniscore, and a fully transparent repayment schedule with zero hidden fees.

### 3.2 The Co-Applicant (Parent/Guardian)
Since students often have "thin credit files," a co-applicant's financial history strengthens the application.
* **Document Responsibilities:** The co-applicant must provide their primary bank statement. The AI engine heavily relies on this to calculate the combined Debt-to-Income (DTI) ratio and average savings.

### 3.3 The Institutional Admin (Bank / College)
Administrators have access to a dedicated partner portal to oversee the BNPL credit lines.
* **Verification Engine:** Admins can view incoming student applications and verify digitized admission letters.
* **AI Explainability:** Admins see exactly *why* a student was approved or rejected. The dashboard provides a detailed "Explainable AI Reasoning" breakdown (Pros and Cons) generated by the AI Risk Engine.

## 4. Key Platform Features

### 4.1 Intelligent Document Digitization
When you upload a PDF (e.g., a bank statement or admission letter), the system does not just store it; it *reads* it. 
* **Native Extraction:** The system attempts to read the raw text from digital PDFs.
* **OCR Fallback:** If you upload a scanned image or a blurry document, the system automatically falls back to Optical Character Recognition (OCR) to digitize the text.
* **Best Practices:** For the fastest approval, ensure PDFs are clearly legible and not password-protected.

### 4.2 Understanding the "Omniscore"
The Omniscore is a proprietary credit score (ranging up to 900) generated by our XGBoost Machine Learning model. It evaluates:
* **Savings Rate & Average Balance:** Healthy, consistent account balances increase the score.
* **Debt-to-Income (DTI) Ratio:** High monthly debt payments relative to income will lower the score.
* **Behavioral Flags:** The system scans for overdrafts, cheque bounces, and high-risk transactions (like excessive gambling/betting).
* **Academic Merit:** Strong academic performance acts as a positive weight in the final underwriting decision.

### 4.3 Automated Fraud Detection & Security
Credixa is equipped with military-grade document scrutiny.
* **Tamper Detection:** The AI Engine scans documents for signs of forgery, illegal calendar dates (e.g., "Feb 30th"), and ledger continuity breaks.
* **Critical Alerts:** If fraud is detected, the application is instantly locked, a heavily penalized Omniscore (12.0) is assigned, and a "CRITICAL ALERT" is logged for the Admin.

## 5. Troubleshooting & FAQs

**Q: What happens if the AI takes too long to process my application?**
A: Credixa features a "Resilient Fallback" pipeline. If the primary Large Language Model (LLM) experiences a network timeout or rate limit, the system gracefully triggers local Regular Expressions (Regex) to extract financial numbers and validate documents, ensuring 99.9% uptime.

**Q: Why was my application flagged as "HIGH RISK" with a low score?**
A: Check the "Reasoning" section on your dashboard. The AI provides complete transparency. Common reasons for rejection include uploading incorrect documents (e.g., uploading an Identity Card instead of a Bank Statement), having a DTI ratio above 60%, or having insufficient average monthly balances.

**Q: Is my financial data secure?**
A: Yes. All inter-service machine learning requests are strictly authenticated via API keys, passwords are bcrypt-hashed, and user sessions are managed securely via Redis and JWTs.
